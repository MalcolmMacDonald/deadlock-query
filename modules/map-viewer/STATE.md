- 2026-10-06 — M4: tile streaming, LOD and memory budget. `ViewerData.tileSource` (a `(tile) => Promise<Uint8Array>`) turns streaming on; `ViewerData.tiles` stays the eager path for fixtures and mocks. `loadBundle(url)` now streams: it fetches only the manifest, entities, collision GLB and baked BVH, never the render tiles. Pieces: `src/tiles.ts` (pure: `parseTileId`/`tileLod` read the `#lod<n>` suffix unless a `lod` field is present, `buildTileIndex` groups LODs into cells with a Three-space box, `lodIndexForDistance` = LOD0 within 1.5 tile diagonals and one LOD coarser per doubling, `selectVisible` = frustum cull + nearest first, `planResidency` = every visible cell gets its coarsest LOD first so there are no holes, nearest cells are upgraded while the budget allows, farthest cells are dropped when even the coarse set does not fit); `src/tileDecode.ts` (`decodeTileGlb`: GLTFLoader with the meshopt decoder, all meshes of a tile merged into one indexed geometry with node transforms baked in, textures and materials dropped; `workerDecoder` pool that falls back to the calling thread when workers cannot start or die; the main-thread GLB path in `scene.ts` now also has the meshopt decoder); `src/tileWorker.ts` + `src/defaultDecoder.ts` (2 module workers via `new Worker(new URL("./tileWorker.ts", import.meta.url), { type: "module" })`, checked to bundle in shell's `vite build`; no `Worker` = decode inline); `src/tileStreamer.ts` (`TileStreamer`: plan per camera, up to 4 tiles fetching/decoding at once nearest first, one LOD shown per cell (the resident one closest to the planned LOD, so a finer tile replaces a coarse one only once it has arrived), LRU eviction of tiles the plan does not want, then farthest planned ones; room is made before a decoded tile is added, so resident bytes never pass the budget; transient decode buffers of at most `maxInFlight` tiles are not counted; decode size is estimated as file size x the last measured inflation until a tile is measured). Budget default 512 MB of decoded geometry (`streaming.budgetBytes`), counted as positions + indices bytes (what the GPU holds). Progress: `ViewerController.progress` is an Effect `Stream` of `StreamStats` (resident/loading/missing/evicted/bytes), `controller.tileStats` the latest, and the canvas carries `data-tile-*` attributes. Picking without a baked BVH rebuilds its mesh BVH when streamed tiles come or go (lazily, on the next pick). Tests: bun unit (`test/tiles.test.ts`; `test/streaming.test.ts`: a lawnmower flight over a 593 MB synthetic map with a 128 MB budget never exceeds it and never leaves a visible cell empty, over-budget views drop the farthest cells, LOD replacement, failed tile, real GLB decode, worker pool fallback) and `bun e2e/streaming.ts` (real heightfield GLBs generated by `e2e/synthetic.ts`, 14 x 14 cells x 3 LODs = 593 MB of tile files, worker decode in Chromium, 100 MB budget: peak resident 100 MB, 350 tiles / 384 MB streamed, 307 evicted, `loadBundle` streams). `bun run test:e2e` runs both e2e scripts.

## Extractor proposals (from the perf pass, nothing changed in map-extractor)
- Site budget: 30 M triangles at about 17 B/triangle (real lite: 87 MB for 5 M) is about 510 MB for LOD0. LOD1 keeps about 68 % of LOD0 on real tiles (error bound stops the simplifier before `--lod-ratio 0.25`), which would add about 350 MB and, with LOD2, push the site past the 900 MB infra budget. Ask: LOD1 ~25 % and LOD2 ~6 % of LOD0 (fall back to `simplifySloppy` when the error bound blocks the target, as `liteRender` does), which brings the three LODs to about 670 MB and cuts far-view triangles about 4x per step. Measure on the real bundle: sum of tile MB per LOD and triangles per LOD.
- Keep LOD0 tiles at 4 to 8 MB (about 250 k to 450 k triangles): small enough that the 4 in-flight loads stay under ~0.1 s of decode each, and large enough that the plan sorts a few hundred cells, not thousands.
- Decoded size is about 44 B per LOD0 triangle (12 positions, 12 or 6 indices, 4 colour per vertex), so the default 512 MB budget holds about 12 M LOD0 triangles; fine for a streamed view, small for flying out at LOD0 (keep `lod0Range` low).
