# contracts — plan

## 1. Purpose & scope
The shared vocabulary between modules: data schemas, web service tags, export functions and a fixture generator. It is intentionally **small and grows slice by slice from real data** (IMPLEMENTATION_PLAN D14) — it is not a big up-front design.

**Non-goals:** no business logic, no UI, no I/O besides schema validation helpers; no C# codegen (queries are TS now); no per-interface versioning machinery.

## 2. Ownership boundary
`modules/contracts/**` → package `@deadlock-query/contracts`. Everyone depends on it; it depends only on `effect`.

## 3. Published surface (by slice)

**Slice 1 (MVP)** — write only after spike S2 (map-extractor) reports what the real data contains:
- `MapBundle`: `manifest.json` `{ schemaVersion, gameBuildId, mapName, tier: "full"|"lite", coordinateSystem{ up:"Z", unit:"source", glbToWorld: Mat4 }, bounds, tiles[{id,bounds,file,bytes,sha256}], collision?{file,format}, entitiesFile, baked?{...} , provenance{extractorVersion, s2vVersion} }`; `entities.json`: `[{ id, class, kind?, position: Vec3, rotation?, team?, lane?, properties }]` where `kind` is the normalised enum the library uses (guardian, walker, patron, healingOrb, creepCamp, zipline, ...), unknown classes preserved.
- `QueryResult`: typed table `{ columns[{name,type: number|string|bool|point|segment|polyline|polygon|entityRef}], rows[][], geometryColumns[], stats{rowCount,compileMs,runMs}, warnings[] }` and pure `exportResult(result,"csv"|"json"|"geojson")`.
- Web service tags + mocks: `MapDataService` (manifest, loadTile, entities, collision bytes), `ViewerService` (loadBundle, camera get/set/flyTo, `setOverlay(layerId, features, style)`, `removeOverlay`, `highlight(ids)`, events stream pick/hover/camera, `captureImage()`), `QueryEngine` (status, `check(source)`, `complete`-free: editor-side intellisense lives in Monaco; `run(source, opts) → Stream<progress|result>`, `cancel`), `SelectionBus`.
- `ModuleDefinition`/`PanelDefinition`/`CommandDefinition` types (IMPLEMENTATION_PLAN §5.5), `DevAuth` service tag (`status`, `login(password)`, `github(request)`).
- `Space`: `glbToWorld`, `worldToThree`, unit helpers, `Vec3`/`Aabb`/`Mat4` plain-array types (tuples, no classes — classes live in spatial-core/query-library).

**Slice 2+ (added when needed):** `Annotation` (features in canonical space + layers), baked-data file *specifications* (BVH, navmesh, sample grid with named channels — implementations in spatial-core; bake manifest fields `semanticsVersion`, `placeholder`), `MapMetadata` (+ `Submission`, `ReviewDecision`), `ScreenshotSet`.

## 4. Uses
Only `effect`.

## 5. Technical design
- Effect `Schema` for every type; `Schema.Type` exported; `bun run gen:schemas` emits JSON Schema (documentation + the Worker/CLI validators).
- `schemaVersion` (semver string) on every top-level document; helper `decodeVersioned(schema, minMajor)` produces a tagged error `UnsupportedSchemaVersion` that tells the user which side to update.
- **Fixtures**: `fixtures/mini-map/` generated by a deterministic script `bun run gen:fixtures` from code (no Valve data): small synthetic arena — 3 lanes, walls with a window, an enclosed building, a high ledge, entity set (guardians per lane, camps, orbs), tiny render GLB and collision, plus `expected/*.json` results for the MVP query. Used by CI and by every module's standalone mode.
- **Real-data contract check** (local only, not in CI): `bun run check:real -- <bundle-dir>` validates an extractor-produced bundle against the schemas and warns about fields the fixture covers but real data lacks. This is what keeps the synthetic fixture honest.
- Mocks: `Mock*` Layers for each service so web modules run without their neighbours.
- Changes are announced in `CHANGELOG.md`; breaking edits to a schema bump that document's `schemaVersion` major and must come with updates requested in other modules' `STATE.md`.

## 6. Milestones
| # | Deliverable | Acceptance |
|---|---|---|
| M0 | Package scaffold, `verify`, `Space` + tests, module/service type skeletons, mock layers | `bun run verify` green |
| M1 | **Slice-1 contract set** (`MapBundle` manifest/entities as shaped by S2 findings, `QueryResult`, services, fixtures) | Extractor, viewer and builder agents can start against fixtures; shipped within days of S2 |
| M2 | Real-data contract check against the first real bundle; adjust schemas | Check passes on real bundle; fixture gaps documented |
| M3 | Slice-2 additions: baked-data specs, `Annotation` | Spec doc + schema + round-trip tests |
| M4 | Slice-3 additions: `MapMetadata`, `ScreenshotSet` | Same |

## 7. Test strategy
Encode/decode round trips, negative cases per validation rule, `Space` property tests (fast-check), fixture generator determinism (snapshot hash).

## 8. Standalone mode
`bun run gen:fixtures && bun test`.

## 9. Risks & open questions
- Contract churn blocks agents → additive changes preferred; announce in `CHANGELOG.md`; consumers log requests in their own `STATE.md`.
- The synthetic fixture must contain enough variety (window wall, closed room, ledge) to test Phase-2 spatial features.

## 10. Definition of done (Slice 1)
Slice-1 contract set stable and used by ≥ 3 modules; real-data check passes; changelog current. Later slices extend the same package.
